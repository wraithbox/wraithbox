# S05 - Command Line Interface

**Purpose:** Specify `wb`, the single user-facing command.

**Requirements:** FR01-drop-in to FR05-parallel-sessions, FR09-approve-unknown, FR12-clipboard, FR13-claude-state to FR17-same-everywhere, SEC03-no-host-exec, SEC10-audit, SEC14-no-fake-approvals, NFR01-startup, NFR06-explained-refusals.

**Tests:** C04-projects

Briefs: B37-terminal-boundary, B42-trust-placement, B46-session-lifecycle

## Design

### Shape

```
wb [wb flags] <command> [command args]
```

`wb` is a dispatcher in the style of `gh` or `git`. Every capability is
a subcommand of the one binary. There is no second CLI.

- **wb flags** come before the command. They are the only arguments
  `wb` itself parses. An unknown flag there is an error, and is never
  passed on.
- **The command** is the first non-flag argument.
- **Command arguments** belong to the command. For agent commands, `wb`
  doesn't parse them at all (S05-01-agent-commands).
- `wb` with no command, `wb help` and `wb --help` print the command
  list. `wb version` and `wb --version` print the version.
- A usage error exits with status 2 and prints the help.

### Global flags

| Flag | Meaning |
|---|---|
| `-C <dir>` | Act as if `wb` was started in `<dir>` |
| `--help`, `-h` | Help |
| `--version` | Version |

### Terminal stream

The guest output that `wb claude` and `wb shell` write passes an
allowlist filter in `wb`. That is boundary 6 of T00-index
(SEC03-no-host-exec). S16-terminal-stream specifies the filter, and
everything else `wb` does at that boundary.

The filter and `wb` treat the stream this way:

- OSC 52 is dropped, because V1 has no clipboard
  (V1-08-no-forward-clipboard).
- Notifications become a bell.
- Links are dropped on screen and listed in the session summary.
- `wb` sets the window title itself.
- `wb` resets the terminal before the summary.
- `wb` passes seven environment variables to the guest.

`wb diff`, logs and audit records show control sequences in guest text
escaped, where a reviewer sees them. Other output outside the stream
removes them.

### Controls

- SEC03-no-host-exec: nothing the agent produces runs on the host
  without the user. It is kept, and extended to the terminal.
- SEC14-no-fake-approvals: the guest can't spoof approvals. It is kept,
  and extended to the terminal.
- FR12-clipboard: clipboard is opt-in, with approval. It is kept,
  because OSC 52 never passes.
- FR01-drop-in: `wb claude` behaves as `claude`. It holds, except that
  `/copy`, notification text, links and Claude Code's own window title
  are lost.

### On WSL

Inside a WSL 2 distribution on a Windows host, `wb` runs in client mode
(FR16-wsl, S12-platforms). It has the same commands and flags, served
by the Windows host's `wb-hostd`.

- The repository, the terminal and `wb land` are on the WSL side.
- VMs, policy, credentials and audit are on the Windows side.

## Decisions

### An allowlist filter on guest output

Guest output that reaches the user's terminal passes an allowlist
filter in `wb` (S16-terminal-stream). The allowlist is the one measured
in X19-terminal-filter, tightened as the security review of PR66 asked.

- **Assumed:** a headless emulator shows what Ghostty and Terminal.app
  show. I62 checks that by eye. Both terminals answer the drain's
  `CSI ? 6 n`. The caps fit later Claude Code versions. Drop counts
  show it when they don't.
- **Decided:** I37 and I30 (B37-terminal-boundary).

### Escape guest text outside the stream, don't strip it

`wb diff`, logs and audit records show control sequences escaped. Other
output still removes them.

- **Why:** a reviewer sees them there. X19-terminal-filter asks for
  escaping in logs.
- **Rejected:** stripping control sequences from all guest text outside
  the stream, as the I37 decision says. This is the one change from it.

### Reset the terminal on exit

`wb` resets the terminal on exit (S16-terminal-stream, "Reset on
exit").

- **Rejected:** running the session on an alternate screen of `wb`'s
  own.
- **Decided:** I37, 2026-10-06.

### The full filter on every stream

A stream that goes to a pipe or a file passes the same full filter as
terminal output (S16-terminal-stream, "Where").

- **Decided:** I37, 2026-10-06.

### Closing the terminal ends the session

Closing the terminal ends the session. S05-02-exit-status-and-signals
says what `wb claude` exits with, and which signals it forwards.

- **Decided:** I46 (B46-session-lifecycle).
