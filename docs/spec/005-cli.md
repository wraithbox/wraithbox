# 005 - Command Line Interface

**Purpose:** Specify the user-facing commands: `wb`, the drop-in for
`claude`, and `wbctl`, the management tool.

**Requirements:** F1–F5, F9, F13–F15, S14, N1, N6.

## `wb`: drop-in for `claude`

- Every argument is passed to `claude` unchanged, so `wb --resume`,
  `wb -p "…"`, `wb mcp list` behave as they would with `claude`. Wraith
  Box's own subcommands live in `wbctl` precisely so that no `claude`
  subcommand, present or future, can collide with them.
- A small set of options are reserved with a `--wb-` prefix and removed
  before passthrough:
  - `--wb-ephemeral` — no persisted state for this session (F14).
  - `--wb-isolated` — run in the isolated VM (S8).
  - `--wb-learn` — learn mode; refused unless the project is trusted (F10).
- Interactive use: raw-mode TTY relay, window-size changes forwarded,
  exit code of `claude` returned. Non-interactive use (pipes, `-p`):
  stdin/stdout streamed, stderr on its own channel.
- Must be run inside a git repository; otherwise it exits with a message
  explaining why (the return path is git, spec 008).
- First run in a repository registers the project, creates its guest
  user and clone, then starts the session. Later runs reuse them.
- On exit, `wb` prints a short summary of the session's returned work
  and the `wbctl` commands to review and land it, e.g.:

  ```
  wraith box: session myrepo-20261003-1412-k3f9 returned 3 commits (+ WIP)
    review: wbctl diff myrepo-20261003-1412-k3f9
    land:   wbctl land myrepo-20261003-1412-k3f9
    ⚠ flagged: package.json scripts changed, .github/workflows/ci.yml changed
  ```

- `wb` never prints approval prompts. The terminal carries the agent's
  output, which the guest controls, so any prompt there could be forged
  (S14). Approvals are system notifications or `wbctl approve`.

## `wbctl`: management

| Command | Purpose |
|---|---|
| `wbctl status` | VMs, their state, running sessions, pending approvals |
| `wbctl sessions [--project P]` | List sessions and their returned work |
| `wbctl diff <session>` | Review returned work with flagged paths highlighted |
| `wbctl land <session> [--branch NAME]` | Fetch returned work into the host repo as a branch; never checks out or merges |
| `wbctl discard <session>` | Drop returned work and the session's guest worktree |
| `wbctl approve` / `wbctl deny` | Answer pending approvals (notification alternative) |
| `wbctl allow <host> [--project P]` | Add an allowlist entry (S5) |
| `wbctl policy show/explain/edit [--project P]` | Effective policy and why a request was allowed or refused (N6) |
| `wbctl learn report [--project P]` | Suggested allowlist from a learn-mode session (F10) |
| `wbctl trust <repo>` / `wbctl untrust <repo>` | Allow repository-supplied configuration (S9) |
| `wbctl cred set/list/rm <binding>` | Manage credentials held by `wb-proxyd` (spec 009) |
| `wbctl audit tail/search` | Read the audit log (S10) |
| `wbctl vm start/stop/suspend/status` | Explicit VM control |
| `wbctl image build/list/use` | Base image management (spec 006) |
| `wbctl shell [--project P]` | Debug shell as the project user, clearly labelled as such |

## Naming

- Project id: stable hash of the repository's real path plus the URL of
  its first remote; a human-readable name is derived from the directory.
- Session id: `<project-name>-<yyyymmdd>-<hhmm>-<4 random chars>`.
- Returned work lands on host branches `wb/<session-id>` by default.
