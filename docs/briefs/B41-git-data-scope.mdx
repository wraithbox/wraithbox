## Sub-decisions

The issue bundles six items. Item 1 is a real fork, with options below. The rest have one recommendation each.

| Item | Recommendation | Now or later |
|---|---|---|
| 1. Ref scope | **A** below: an export repository with only the `HEAD` branch and refs the user adds in project settings. | now |
| 2. Untracked files | Scan carried-in untracked files, and the staged and unstaged diff, with the image-seal secret scanner (S06-vm-lifecycle). Skip a file that matches and list it in the session summary, as for oversize files. | now |
| 3. Remote URLs | Strip user names, passwords and query strings from every URL that reaches the guest. Rewrite SSH remotes to HTTPS for the guest, shared with I47. | now |
| 4. Host git | Require a minimum git version, checked by `wb setup` and at each session start. Keep `receive.fsckObjects` and `receive.maxInputSize`. Don't bundle git (GPL-2.0, against the license rule of S10-tech-stack). A receive side in Go is a later option. | now |
| 5. Ref restriction | `receive.hideRefs` set to hide everything but `refs/heads/wb/<session-id>/`. A Go filter on the command list is optional on top. | after X07-git-round-trip |
| 6. Landing lifecycle | `wb discard` deletes the session's refs and guest worktree. `wb-hostd` runs `git gc` on the landing repository after land and discard. A size cap per project, refused with an explanation (SEC13-bounded-resources, NFR06-explained-refusals). | now |

## Options for the ref scope (item 1)

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Export repository

`wb-hostd` keeps a bare repository per project (`projects/<id>/export.git`), fetches only the selected branches into it from your repository, and serves `upload-pack` from there. Objects reachable only from other refs are never in it.

- **Cost:** one local fetch per session start, which copies new objects only, and the disk space of one more copy.
- **Keeps:** <Badge text="SEC04-no-guest-secrets" variant="success" />

</div>
<div class="wb-option">

### B. Hidden refs, protocol v0

What the issue proposes (`uploadpack.hideRefs`), plus forcing git's older protocol v0, which refuses a fetch of an object it didn't advertise.

- **Cost:** none extra, but v0 is slower for large repositories.
- **Weakens:** git's documentation says other ways to fetch hidden objects exist. <Badge text="SEC04-no-guest-secrets" variant="caution" />

</div>
<div class="wb-option">

### C. Hidden refs only

The issue's proposal as written.

- **Cost:** none.
- **Weakens:** with protocol v2, the guest fetches a hidden branch's commit by its ID. <Badge text="SEC04-no-guest-secrets, spec change" variant="danger" />

</div>
<div class="wb-option">

### D. Leave the spec as is

Advertise every ref, as `upload-pack` does by default.

- **Cost:** none. Every local branch, tag, note and stash reaches the guest.
- **Weakens:** <Badge text="SEC04-no-guest-secrets, spec change" variant="danger" />

</div>
</div>

<Aside type="note" title="Missing from the issue">
- **Hidden refs are not access control.** With `uploadpack.hideRefs` hiding a branch, git 2.56 still sent that branch's commit to a client that asked for it by ID over protocol v2. Protocol v0 refused. Git's own documentation says to keep private data in a separate repository. A commit ID leaks easily: `git cherry-pick -x` writes the full ID of the source commit into the message.
- **Git can enforce the ref restriction without hooks.** `receive.hideRefs` rejects a push to any hidden ref. Hiding `refs/` and exposing `refs/heads/wb/s1/` let a push to `refs/heads/wb/s1/a` through and rejected `main`, a tag, `wb/s2/a` and `wb/s1x`. Item 5 is then a git setting that X07-git-round-trip confirms.
- **Tracked changes too.** The carry-in diff of staged and unstaged changes can also hold a new token, so item 2's scan covers it as well.
- **Identity depends on the URL.** Project identity hashes the first remote URL (S05-cli). A token in that URL changes the project when the token rotates, and "first" is alphabetical. B42-trust-placement takes this up.
</Aside>

<details>
<summary>Details and glossary</summary>

**Why the guest can name a hidden commit.** The ID of a commit is in plain sight more often than it seems: cherry-picks with `-x`, reverts ("This reverts commit …"), issue comments, CI logs. With protocol v2 the guest asks for that ID and receives the commit with its whole history, unless the object isn't in the served repository at all, which is what an export repository ensures.

**Why a minimum version.** Each `receive-pack` parses packs the guest built, and `wb land` later runs your own git against them. Git has had security fixes in these code paths, and Apple's git ships them later than upstream. `wb setup` names the git it uses and refuses one below the minimum, with the reason.

**Glossary**

- **Ref:** a name for a commit, such as a branch (`refs/heads/main`), a tag, a note, or the stash.
- **Advertise:** the list of refs the serving side offers at the start of a fetch.
- **`upload-pack` / `receive-pack`:** the host-side git programs that serve a fetch and accept a push.
- **Pack:** the compressed bundle of objects that a fetch or push transfers.
- **Protocol v0 / v2:** git's older and newer wire protocols. v2 is the default.
- **Landing repository:** the bare repository in Wraith Box's state that receives the guest's pushes (S08-workspace-and-git).
- **Userinfo:** the `user:token@` part of a URL.

</details>
