## Options for what the blocked client sees

<Aside type="note" title="Options">
The issue gives one proposal, option A. Options B to D are this brief's. The sub-decisions after the cards are the issue's other points, with a recommendation each.
</Aside>

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Hold the answer, then refuse uncached

`wb-netd` holds the DNS answer while the notification is open, up to 4 seconds. An approval in that window gets a real answer. After that, or on deny, it answers NXDOMAIN with a negative TTL of zero. The next lookup then reaches `wb-netd` again.

- **Cost:** a pending-query table in `wb-netd` and a short wait on every unknown name. A user who answers in time sees the tool work on the first try.
- **Keeps:** <Badge text="SEC05-default-deny" variant="success" /> <Badge text="SEC14-no-fake-approvals" variant="success" />

</div>
<div class="wb-option">

### B. Refuse at once, uncached

As today, plus a negative TTL of zero. The tool fails, and the agent must notice and retry after the user approves.

- **Cost:** smallest. Every approval costs the agent a failed step.
- **Keeps:** <Badge text="SEC05-default-deny" variant="success" />

</div>
<div class="wb-option">

### C. Resolve every name, hold the connection

DNS gives every name a synthetic address. `wb-netd` holds the TCP handshake of an unknown name until the user answers, and resets it on deny. macOS waits 75 seconds for a handshake by default, against a few seconds for DNS.

- **Cost:** changes the DNS design in S07-egress-gateway, and the guest's view of which names exist. Needs a spike in X03-network-path.
- **Keeps:** <Badge text="SEC05-default-deny if no stream reaches wb-proxyd unapproved" variant="caution" />

</div>
<div class="wb-option">

### D. Leave the spec as is

NXDOMAIN at once, with whatever negative TTL the code picks. If it caches, "the next lookup succeeds" is false.

- **Cost:** none now. Approvals appear not to work.

</div>
</div>

## Sub-decisions

| Point | Recommendation | Decide now? |
|---|---|---|
| Negative TTL | NXDOMAIN carries an SOA record with TTL 0 and MINIMUM 0. | yes |
| Silent deny list | Guest OS names are refused without a notification, and the image build turns those services off at the source. Each refusal is still audited. | rule now, list after X03-network-path |
| Coalescing | One open request per name. Repeated lookups join it. | yes |
| Cap on open requests | A fixed number open at once. Over the cap, names are refused and audited, and `wb status` shows the count. | per VM now, per session after I36 |
| Timeout | A request stays in `wb status` until answered or until its session ends, and is audited as expired. | yes |
| Display | Show the name as received (punycode form). Show the Unicode form next to it only with a warning when it mixes scripts or uses confusable characters. Escape every byte outside letters, digits, hyphen, and dot. | yes |
| "Allow for this session" | Needs to know which session asked. | after I36 |

<Aside type="note" title="Missing from the issue">
- **A 5-second hold meets the guest's retry.** The macOS stub resolver waits 5 seconds (`RES_TIMEOUT`) before it sends the query again, and tries twice by default. A hold of 5 seconds ends just as the retry is sent. This brief recommends 4 seconds, with coalescing so the retry joins the open request. The guest uses `mDNSResponder`, which may time out differently, so X03-network-path should measure it.
- **DNS names are bytes, not text.** A label on the wire can carry any byte, including control characters, spaces, and dots. S09-policy-credentials-audit strips control sequences, but the display rule must also escape the rest, or a label holding a dot and a space can read as a different name in the notification.
- **Notifications are an attack surface.** The guest decides which names are looked up, so it can flood the user to wear down attention (T04-bad-approvals). The cap on open requests is the control, and the spec should say so.
- **Under the I36 recommendation, a session is the VM.** B36-flow-attribution recommends enforcing per VM. Then "allow for this session" and the per-session cap work per VM until a label source exists.
</Aside>

## Evidence

- <Badge text="verified" variant="success" /> Unknown names get NXDOMAIN and raise an approval, and "after approval, the next lookup succeeds" (S07-egress-gateway, "DNS").
- <Badge text="verified" variant="success" /> A negative answer is cached for the smaller of the SOA record's TTL and its MINIMUM field. Negative answers without an SOA record "SHOULD NOT be cached" ([RFC 2308](https://www.rfc-editor.org/rfc/rfc2308.html), sections 3 and 5).
- <Badge text="verified" variant="success" /> The macOS resolver library waits `RES_TIMEOUT` = 5 seconds between retries and tries `RES_DFLRETRY` = 2 times (`resolv.h` in the macOS SDK, `man 5 resolver`).
- <Badge text="verified" variant="success" /> macOS waits 75 seconds for a TCP handshake by default (`sysctl net.inet.tcp.keepinit` = 75000 on the host). The guest default is assumed to match.
- <Badge text="verified" variant="success" /> Approvals are notifications or `wb approve`, never in the agent terminal, and guest-influenced text is stripped of control sequences (S09-policy-credentials-audit, "Approvals"). The user's attention is an asset (T00-index, "Model").
- <Badge text="verified" variant="success" /> I51 is blocked by I36 and by I17 (X03-network-path), on GitHub.
- <Badge text="assumed" variant="caution" /> That the guest's `mDNSResponder` honors a zero negative TTL and retries on the same schedule as the resolver library. X03-network-path can check both while it lists background names.
- <Badge text="assumed" variant="caution" /> That a 4-second hold is long enough for a user to answer in a useful share of cases. Measured in use during V1-M5-approvals.

## What this unblocks

- The approval flow section of S09-policy-credentials-audit and the approval work in V1-M5-approvals (FR09-approve-unknown, SEC14-no-fake-approvals).
- It waits on X03-network-path (I17) for the silent deny list, and on I36 for anything per session.

<details>
<summary>Details and glossary</summary>

**Why not answer `SERVFAIL` instead of NXDOMAIN.** A temporary failure makes some tools retry by themselves. It also says "try again" to a name the user may deny, and resolvers handle it less predictably than NXDOMAIN. Option A gets the retry benefit for the names the user approves in time.

**Glossary**

- **NXDOMAIN:** the DNS answer "this name doesn't exist".
- **Negative TTL:** how long a resolver remembers an NXDOMAIN before asking again.
- **SOA record:** a DNS record that, in a negative answer, carries the negative TTL.
- **Stub resolver:** the part of the guest OS that sends DNS queries for programs. On macOS it is `mDNSResponder`.
- **Punycode:** the ASCII form of an internationalized name (`xn--…`), which is what DNS carries.
- **Confusable characters:** letters from different scripts that look alike, such as Latin `a` and Cyrillic `а`.
- **Coalescing:** treating repeated requests for the same name as one.

</details>
