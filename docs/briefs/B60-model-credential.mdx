**Partly answered 2026-10-12: yes for a long-lived subscription token.** Source: I60, X01-model-credential. The spec changes wait for the decisions below (I215). API key mode and the browser login are in I15.

<Aside type="tip" title="What we learned">
**Yes, for a long-lived token.** With a placeholder in `CLAUDE_CODE_OAUTH_TOKEN` and the throwaway proxy putting the real token from `claude setup-token` into `Authorization: Bearer`, Claude Code answered in `-p`, `-p --resume` and an interactive session, and opened an interactive `--resume`. It sent the token only to `api.anthropic.com`, and the real token was in no file and no Keychain item it made. You are deciding which other hosts Claude Code may reach. Recommended: **A**, the model only, with Claude Code's nonessential traffic turned off in the guest. Then I215 writes the model API profile into S07-egress-gateway and S09-policy-credentials-audit.
</Aside>

## The hosts outside the model API

| Decision | Host and what it does | Recommended |
|---|---|---|
| 1. Telemetry | `http-intake.logs.us5.datadoghq.com`: Datadog log intake, with a key built into Claude Code and without the user's token. 5 requests. Anthropic's own event log on `api.anthropic.com` (`/api/event_logging/v2/batch`) carries the user's token, 10 requests | Datadog outside the profile, as S07-egress-gateway says today. Telemetry off in the guest, which also stops the event log |
| 2. Updates | `downloads.claude.ai`: the auto-updater fetched the 2.1.296 build in each interactive session, and the plugin marketplace one plugin archive | Outside the profile, updater off in the guest. The image sets the version |
| 3. Changelog | `raw.githubusercontent.com`: one GET of Claude Code's `CHANGELOG.md` at interactive start | Outside the profile |

## Options

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. The model only

The profile allows the `api.anthropic.com` paths Claude Code used and `platform.claude.com` `/v1/oauth/hello`. The token goes to `api.anthropic.com` only. The guest sets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, which is meant to turn off telemetry, error reports and the updater, so Claude Code doesn't ask for the other hosts (assumed, see Evidence).

- **Cost:** a Claude Code update needs a new image. No update notice or changelog in the guest.
- **Gives:** two allowed hosts, the fewest of the options. Datadog doesn't get usage data.
- **Keeps:** <Badge text="SEC04-no-guest-secrets" variant="success" /> <Badge text="SEC05-default-deny" variant="success" /> <Badge text="SEC07-dep-gate" variant="success" />

</div>
<div class="wb-option">

### B. The model and updates

As A, plus `downloads.claude.ai` for the updater and the plugin marketplace. Telemetry stays off.

- **Cost:** each guest downloads new builds itself and runs them, and drifts from its image. In the spike it fetched a build at each interactive start.
- **Gap:** a binary and plugins come in from outside the dependency gate.
- **Keeps:** <Badge text="SEC04-no-guest-secrets" variant="success" /> <Badge text="SEC05-default-deny" variant="success" /> <Badge text="SEC07-dep-gate" variant="caution" /> a download host outside the gate

</div>
<div class="wb-option">

### C. Everything Claude Code reached

As B, plus Datadog and `raw.githubusercontent.com`, with telemetry on.

- **Cost:** usage data goes to Datadog and Anthropic from every session.
- **Gap:** `raw.githubusercontent.com` serves any file of any public GitHub repository, so allowing it for a changelog opens that whole host to the guest.
- **Keeps:** <Badge text="SEC04-no-guest-secrets" variant="success" /> <Badge text="SEC05-default-deny" variant="caution" /> a broad content host allowed <Badge text="SEC07-dep-gate" variant="caution" />

</div>
</div>

## Evidence

- <Badge text="verified" variant="success" /> `-p` answered `pong`, `-p --resume` answered `I replied with "pong".` in the same session, and the interactive session answered one question, all with a placeholder `CLAUDE_CODE_OAUTH_TOKEN`. Source: X01-model-credential, "Answer", and the run's `p.json`, `resume.json` and proxy log.
- <Badge text="verified" variant="success" /> All 36 requests with a credential sent it as `Authorization: Bearer` to `api.anthropic.com`, with `anthropic-beta: oauth-2025-04-20`. The proxy replaced the placeholder in each. No other host got the placeholder. Source: the proxy log, X01-model-credential, "Hosts".
- <Badge text="verified" variant="success" /> The real token wasn't in any file of the test user's home, and Claude Code didn't make a Keychain item for it. Source: X01-model-credential, "What Claude Code stored".
- <Badge text="verified" variant="success" /> The updater, the plugin marketplace, the changelog and the reachability checks ran only in interactive sessions. Source: the proxy log's timestamps.
- <Badge text="verified" variant="success" /> The variables `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_TELEMETRY` and `DISABLE_AUTOUPDATER` appear in the Claude Code 2.1.289 binary. Source: a string search of the binary.
- <Badge text="assumed" variant="caution" /> That those variables stop the Datadog, event log, update and changelog requests, and that Claude Code works when those hosts are denied. The spike didn't run either. The model API profile work (I215) or a rerun of the spike with the variable set would show it.
- <Badge text="assumed" variant="caution" /> That a `setup-token` token is valid for longer than a session, and the guest doesn't need to refresh it. The spike didn't see a refresh, and `claude setup-token --help` calls the token long-lived without giving a lifetime.
- <Badge text="assumed" variant="caution" /> That API key mode works the same way, from OpenShell's Claude Code provider (X00-index). The spike saw only that the placeholder goes out as `x-api-key` and is replaced.
- <Badge text="inferred" variant="note" /> That the host's Claude Code and the guest's don't race on a refresh: `setup-token` makes a token of its own, separate from the host's login.

## What this unblocks

- I215: the model API profile in S07-egress-gateway and the model credential in S09-policy-credentials-audit.
- I15 keeps the browser login and API key mode. This answer narrows it: a subscription user has a mode that works without them.

<details>
<summary>Details and glossary</summary>

**The token stays in the proxy, out of the guest.** Claude Code only needs a string that looks like a token. The proxy, which runs on the host, sees each request in clear because it inspects TLS, and swaps the placeholder for the token just before it leaves the Mac. A guest that leaks its placeholder leaks nothing that works anywhere else.

**What `api.anthropic.com` serves besides the model.** The organization's limits, remote managed settings (404 here: none set), feature flags, Anthropic's event log, a bootstrap call that refused this token every time without harm, and the public MCP server registry. Requests to every one of these paths but the MCP registry hold the token. The profile would allow these paths and no others.

**Glossary**

- **`claude setup-token`:** a Claude Code command that signs in with a subscription once and prints a long-lived token, for use where no browser login is possible.
- **`CLAUDE_CODE_OAUTH_TOKEN`:** the environment variable from which Claude Code reads such a token.
- **Placeholder:** a fake value with the token's prefix and length, which the guest holds instead of it.
- **Profile:** the built-in list of hosts and paths `wb-proxyd` allows for one purpose, here the model API.

</details>
