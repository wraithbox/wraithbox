---
title: How does an image get full Xcode and the simulator runtimes?
description: From the host. Wraith Box copies the host's own Xcode, and runtimes the user exported on the host, onto a read-only disk it builds, and root installs both in the guest during the image build, first launch included.
---

<Aside type="tip" title="You are deciding">
The maintainer already decided that Xcode comes from a read-only disk image the host builds (I194, 2026-10-16). This change says how. Still open: whether the build **requires that you accepted Xcode's license on the host** (recommended: yes, A), and whether the **simulator runtimes also come from the host** (recommended: yes, the user exports them with one `xcodebuild` command, C). Accepting both puts S06-14-xcode-image in the specs as written and unblocks IMG.8, once I624 has measured the signature checks.
</Aside>

## Options

### The license

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Require the host's acceptance

The build refuses with `xcode-license-not-accepted` unless the host's record says you accepted the license of this exact Xcode build. The guest then accepts it for the copy. An image with Xcode never leaves this Mac, and `wb image build` says once that it copies your Xcode into the image.

- **Cost:** after each Xcode update you open Xcode once, or run `sudo xcodebuild -license`, before the next build.
- **Controls:** none touched.

</div>
<div class="wb-option">

### B. Accept in the guest only

The build runs `xcodebuild -license accept` in the guest without looking at the host, and says so.

- **Cost:** none for you. Wraith Box accepts a license on your behalf that you may never have seen for that version.
- **Controls:** none touched.

</div>
</div>

**The case for B.** A host that has Xcode installed and has run it has almost always accepted the license. A adds a check that rarely fails. Recommendation A, with medium confidence. It would change if I624 finds the host's record too hard to read without running `xcodebuild`.

### The runtimes

<div class="wb-options">
<div class="wb-option" data-recommended>

### C. Exported on the host

You run `xcodebuild -downloadPlatform iOS -exportPath <data>/xcode-runtimes` once on the host. The build checks Apple's signature on each runtime and puts it on the same read-only disk, and root imports it in the guest.

- **Cost:** one command per runtime version, and the runtime (about 8 GB) is stored twice on the host.
- **Keeps:** <Badge text="SEC05-default-deny" variant="success" />

</div>
<div class="wb-option">

### D. Downloaded in the guest

The build VM gets a network and downloads the runtime itself, as X06-guest-xcode did.

- **Cost:** Apple's runtime hosts are expected to refuse an inspected connection, so they would need pass mode, which Wraith Box never sets itself. Each would be an uninspected channel out of the guest.
- **Weakens:** <Badge text="SEC05-default-deny" variant="caution" />, by a spec change to the pass rules.

</div>
</div>

**The case for D.** No step for the user, and the guest gets exactly what Xcode asks for. Recommendation C, with high confidence: D needs the build VM's network and a pass exception that today's rules forbid.

## Evidence

- <Badge text="verified" variant="success" /> Copying the host's Xcode from a read-only raw disk, then `-license accept` and `-runFirstLaunch` as root, worked without an Apple ID in 202 s. Source: X06-guest-xcode, "Measurements".
- <Badge text="verified" variant="success" /> `xcodebuild -downloadPlatform iOS` didn't need an Apple ID in the guest (8.05 GB, 1202 s). Source: same.
- <Badge text="verified" variant="success" /> The Layer 2 build profile reads `/Library/Developer`, which the first launch fills. Source: S13-02-filesystem-profile, "Xcode build profile".
- <Badge text="inferred" variant="note" /> Only root can write `/Library/Developer`, so a project user can't run the first launch. Source: S06-08-projects-and-sessions (project users aren't admins).
- <Badge text="assumed" variant="caution" /> That `-exportPath` works on the host without an Apple ID, that an exported runtime has a signature the host can check, and that `-importPlatform` works offline from a read-only disk. I624 measures each, and the build refuses until the checks are known.

## What this unblocks

- IMG.8, the Xcode variant, in V1-M7-image-build.
- The simulator profile of B20-guest-xcode decision 2 (I196) gets images with runtimes.

<details>
<summary>Details and glossary</summary>

**Why not a shared folder.** Sharing a host folder with the guest is what SEC02-no-host-fs-share forbids. A disk image the host builds is a copy, attached read-only, and deleted after the build.

**Why copy the app again in the guest.** The guest disk is read-only and is detached after the build. Xcode has to be on the image's own disk.

**Glossary**

- **Simulator runtime:** the iOS system that the iOS simulator boots, about 8 GB, installed separately from Xcode.
- **First launch:** `xcodebuild -runFirstLaunch`, which installs the system parts Xcode needs into `/Library`.
- **Pass mode:** a host whose TLS traffic `wb-proxyd` forwards without inspecting it (S07-07-hosts-and-modes).

</details>
