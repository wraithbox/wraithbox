## Options

The issue lists the generated-code question without options. These are mine.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Commit generated code

`buf generate` writes Go and Swift code into the packages, and the result is committed. `mise run ci` regenerates and fails on any difference, and runs `buf lint` and `buf breaking` against `main`.

- **Cost:** generated diffs in pull requests. Generated paths need explicit exclusions from cspell, `swift format lint` and SwiftLint.
- **Gains:** a fresh clone builds with plain `go build` and `swift build`, on every OS, without `buf`.

</div>
<div class="wb-option">

### B. Generate at build time

Every build and test task runs `buf generate` first, and Git ignores the output.

- **Cost:** `go build` from a fresh clone fails. The Go tasks on Windows must stay single plain `cmd.exe` commands (S02-toolchain). Each one then needs a generate step in front. Xcode builds need the step too.

</div>
<div class="wb-option">

### C. Swift by build plugin, Go committed

Go code is committed as in A. The Swift package generates its code at build time with a SwiftPM build plugin.

- **Cost:** two mechanisms for one contract. `buf` no longer checks the Swift side, and the plugin must be pinned through `Package.resolved`.

</div>
</div>

Each option leaves the `SEC*` controls unchanged. The contracts themselves serve SEC11-root-gains-nothing: every handler that reads guest bytes gets a fuzz target (S11-verification-and-spikes).

<Aside type="note" title="Missing from the issue">
**Not every link is gRPC.** S04-architecture says "All IPC is protobuf over gRPC". gRPC can't pass file descriptors, so the `wb-vmd` hand-off of S04-architecture and S07-egress-gateway needs a small Unix socket channel next to the gRPC one. The stream from `wb-netd` to `wb-proxyd` is a byte stream with a header (S07-egress-gateway, "Connections"). S04-architecture needs a sentence for both: protobuf messages everywhere, gRPC where there is a request and a reply.

**Committed code meets the prose and Swift gates.** cspell checks every tracked file, and SwiftLint fails on long files. Generated Swift and Go code would fail both, so option A adds path exclusions. That is not a weakened gate, because nobody writes those files by hand. It still changes a checked-in rule, so the maintainer should approve it explicitly.
</Aside>

<details>
<summary>Details and glossary</summary>

**Why `buf breaking` matters here.** `wb-guestd` in an old image may talk to a newer `wb-hostd` (I48). `buf breaking` compares the `.proto` files with those on `main` and fails on a change that would break an old peer, such as a renamed field. That turns the compatibility rule into a check instead of a review habit.

**Why strict settings.** A misspelled key in `config.toml`, such as a resource limit, would otherwise be ignored without a word. An error that names the key is what NFR06-explained-refusals asks for.

**Glossary**

- **protobuf (`.proto`):** a language-neutral way to describe messages. Code generators turn one description into Go and Swift types.
- **gRPC:** remote procedure calls over HTTP/2 using protobuf messages.
- **`buf`:** a tool that lints `.proto` files, checks for breaking changes, and runs code generators.
- **Plugin:** a code generator `buf` runs, one per language.
- **Drift:** committed generated code that no longer matches what the generator would make from the current `.proto` files.
- **`SCM_RIGHTS`:** the Unix mechanism for passing an open file descriptor from one process to another over a Unix socket.

</details>
