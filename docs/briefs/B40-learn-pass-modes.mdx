<Aside type="tip" title="You are deciding">
Whether learn mode may open egress to any host, and who may put a host in pass mode. Recommended: **A**, learn mode refuses unknown names and collects them for `wb learn report`, which keeps SEC05-default-deny as written. The issue recommends **B** instead, which needs SEC05-default-deny rewritten. Pass mode: a user-only, audited list. Either way, S07-egress-gateway gets the rules and T00-index the residual risk.
</Aside>

## Learn mode options

<Aside type="note" title="Options and recommendation">
The learn-mode options are the issue's. The issue recommends B. This brief recommends A, because B and C weaken SEC05-default-deny, and AGENTS.md doesn't allow that without a spec change the maintainer makes on purpose. If you prefer B, its card lists the guardrails the issue attaches to it.
</Aside>

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Collect and refuse

An unknown name is refused as usual, but no notification is shown. The name goes on the session's list. At session end, or with `wb learn report`, the user approves the list in one batch.

- **Cost:** learning takes more than one run, because the agent stops at the first refused host and doesn't reach the hosts behind it. Close to normal operation with quieter prompts.
- **Keeps:** <Badge text="SEC05-default-deny" variant="success" /> <Badge text="SEC06-repo-writes" variant="success" /> <Badge text="SEC07-dep-gate" variant="success" />

</div>
<div class="wb-option">

### B. Open egress, written down

As written today: any name resolves and every connection is allowed and inspected. A new accepted risk in T00-index says egress is open for that session. The issue adds a confirmation outside the agent terminal for each learn session.

- **Cost:** spec wording, plus the confirmation step. One learn session finds everything in one run.
- **Weakens:** <Badge text="SEC05-default-deny during learn sessions, spec change" variant="danger" />
- **Keeps:** <Badge text="SEC04-no-guest-secrets" variant="success" />

</div>
<div class="wb-option">

### C. Open for reads only

New hosts are reachable for `GET` and `HEAD`. Data still leaves in URLs and headers.

- **Cost:** the same spec change as B, for a narrower channel. Code can still leave in a URL.
- **Weakens:** <Badge text="SEC05-default-deny during learn sessions, spec change" variant="danger" />

</div>
</div>

<Aside type="note" title="Missing from the issue">
- The issue says S03-requirements records the exceptions. Since the ID split, S03-requirements only points at the indexes. An exception goes into the SEC05-default-deny text in SEC00-index and an accepted risk in T00-index.
- S07-egress-gateway doesn't say whether learn mode still enforces the rules of hosts that are already known: the git hosting profile (SEC06-repo-writes), the dependency gate (SEC07-dep-gate) and placeholder binding. Under B they must stay on. Otherwise learn mode also opens pushes to any repository.
- Pass mode is not a SEC05-default-deny exception. A pass host is still one named host, and the SNI check holds. On a pass host, `wb-proxyd` doesn't apply HTTP policy, the dependency gate or credential replacement, so on a git host or a registry it would switch off SEC06-repo-writes and SEC07-dep-gate. The recommendation below refuses pass for those hosts.
</Aside>

## Evidence

- <Badge text="verified" variant="success" /> Learn mode: "DNS resolves any name and connections are inspected and allowed" (S07-egress-gateway, "Approvals and learning"). FR10-learn-mode limits it to trusted repositories, and S05-cli refuses `--learn` otherwise ("Session flags").
- <Badge text="verified" variant="success" /> SEC05-default-deny: "Only allowlisted hostnames are reachable", with no exception in SEC00-index. AGENTS.md: a security control is never weakened to make something work.
- <Badge text="verified" variant="success" /> Pass mode relays TLS bytes unchanged and is "a documented residual channel" (S07-egress-gateway, "Modes, per host"). T01-allowed-channels doesn't mention pass hosts, and no spec lists them.
- <Badge text="verified" variant="success" /> Credential replacement and HTTP policy run only on inspected hosts (S07-egress-gateway, "Credential replacement" and "HTTP policy").
- <Badge text="verified" variant="success" /> Repository configuration can never switch a host to pass (S09-policy-credentials-audit, "Repository-supplied configuration").
- <Badge text="verified" variant="success" /> The threat model assumes prompt injection in content a trusted project reads (S03-requirements, "Problem"), so trusting the repository doesn't make an open learn session safe.
- <Badge text="inferred" variant="note" /> A host can't be both pass and credential-bound in a useful way: pass never terminates TLS, so `wb-proxyd` has nowhere to inject the credential.
- <Badge text="assumed" variant="caution" /> That option A finds a project's hosts in two or three runs. It depends on how deep the chain of hosts behind a refused one goes. A trial on real projects during V1-M5-approvals would show it. The decision can go ahead without a spike.

## What this unblocks

- The learn-mode work in V1-M5-approvals (FR10-learn-mode), and the pass-mode rules that V1-M3-network-floor needs before its conformance cases.
- I47, whose raw TCP entries are proposed "in the same class as pass mode, with the same restrictions".
- The decision itself waits on no spike.

<details>
<summary>Details and glossary</summary>

**Why the confirmation step in B matters.** `--learn` is a flag on `wb claude`. A shell alias or a script the user forgot about could add it to every session. The issue's guard is a per-session confirmation through a notification or `wb approve`, which the guest can't fake (SEC14-no-fake-approvals).

**What A looks like for the user.** `wb claude --learn` runs without approval notifications. Each refused name is listed in the session summary and in `wb learn report`, together with the program label if one exists. The user then runs `wb allow` for the names they accept, or approves the list from the report.

**Glossary**

- **Default-deny egress:** only hosts on the allowlist are reachable, and everything else is refused.
- **Learn mode:** a session mode for trusted projects that records which hosts the project needs.
- **Inspect mode:** `wb-proxyd` decrypts the connection with its own certificate, applies rules and injects credentials, then connects upstream.
- **Pass mode:** `wb-proxyd` checks the host name and relays the encrypted bytes unread.
- **SNI:** the host name a TLS client names in its first message.
- **Residual risk:** a known gap written down in T00-index rather than closed.

</details>
