## Decision 1: the mount rule

Decidable now.

| Choice | Recommendation | Why |
|---|---|---|
| Where the rule goes | A new control in SEC00-index, cited from S06-vm-lifecycle | It protects the host from guest input, like SEC02-no-host-fs-share. A control in SEC00-index can't be weakened to make something work (`AGENTS.md`). A sentence in S06-vm-lifecycle can. |
| When the exception ends | At the image's first boot | "Before untrusted code has run", the issue's wording, is hard to judge: provisioning installs Homebrew packages, which run third-party code. The first boot is a clear point. |

The issue says the rule goes in S03-requirements or S06-vm-lifecycle. Requirements are now in SEC00-index, and S03-requirements only points to them.

## Decision 2: what the data disk must keep

The target is decidable now. The settings that meet it wait on the spikes. The options are the brief's, built from the issue's proposal.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Keep state and commits, let caches go

Write the target into S06-vm-lifecycle now. After X05-fs-benchmark and X08-data-disk, pick the cheapest setting that meets it: full sync on the data disk if X05-fs-benchmark finds the cost small, or a small fully synced disk for homes next to a relaxed one for caches and build output.

- **Cost:** maybe a second data disk. X08-data-disk already tests homes on a second disk.
- **Keeps:** <Badge text="FR13-claude-state" variant="success" /> <Badge text="NFR02-fs-speed" variant="caution" />

</div>
<div class="wb-option">

### B. Relaxed disk, push state out often

Keep relaxed settings for speed. `wb-guestd` pushes work to the landing repository and exports Claude Code state to the host on a timer.

- **Cost:** a state export the host stores but must not parse, and a restore path. Loses whatever came after the last push.
- **Keeps:** <Badge text="NFR02-fs-speed" variant="success" /> <Badge text="FR13-claude-state" variant="caution" />

</div>
<div class="wb-option">

### C. Leave the spec as is

Relaxed settings, and the data disk counts as something the host can rebuild.

- **Cost:** none now. A host crash can lose a project's Claude Code history and the commits not yet pushed, or the whole data disk.
- **Weakens:** <Badge text="FR13-claude-state" variant="danger" />, which needs a requirement change.

</div>
</div>

<Aside type="note" title="Missing from the issue">
**The loss can be the whole disk.** The issue says relaxed settings lose recent writes. Apple's header for the no-sync mode says more: on a host panic or power loss "the state of blocks on disk and their order is undefined", and the image "cannot safely be reused on failure". On a shared work VM that is every trusted project's state at once.

**macOS 27 may remove the build-time exception.** The macOS 27 SDK adds `VZMacGuestProvisioningOptions`: on the first boot the framework configures a user account and the initial setup, with no host writes into the disk. It needs macOS 27 on both host and guest, and NFR04-host-platforms allows macOS 15 hosts. X17-image-build (I28) should test it, and the exception can then shrink to older hosts or go.

**The image seal must not mount either.** S06-vm-lifecycle doesn't say where the seal's secret scan runs. If it mounts the provisioned image on the host, it breaks the rule, because provisioning booted the image. It has to run in the guest through `wb-guestd`.

**Recovery goes through the guest.** Under the rule the host can't rescue Claude Code state by mounting a broken data disk. S06-vm-lifecycle should say recovery needs a booted guest.
</Aside>

<details>
<summary>Details and glossary</summary>

**Why mounting is dangerous.** A filesystem driver in the host kernel trusts the on-disk structures more than a network parser trusts packets. A crafted APFS or HFS+ volume is a known way to attack a kernel. The guest has root, so it can write any bytes to its disks. Mounting a guest disk would add a third channel next to the two in S04-architecture, the host-guest socket and Ethernet frames, which are the only places the host is meant to read guest data.

**What still counts as allowed.** Cloning a disk file (APFS clone), copying it, deleting it, and attaching it to a VM handle bytes without interpreting them. The rule is about interpreting the filesystem: mounting, `fsck`, scanning files.

**Glossary**

- **Data disk:** the second virtual disk of a VM, holding project users' homes and workspaces. An image update leaves it in place.
- **Sync mode:** how the host handles the guest's "write this to permanent storage now" requests. Full honors them, `fsync` passes them to the drive, none ignores them.
- **Host crash:** a host kernel panic, power loss, or forced restart. A clean shutdown of the VM is not a crash.
- **Provisioning:** the steps `wb image build` runs after installing macOS, through `wb-guestd`.
- **Setup Assistant:** the macOS first-boot screens that create the first user account.
- **Image seal:** the scan for secrets before an image can be used (S06-vm-lifecycle).

</details>
