<Aside type="tip" title="You are deciding">
Whether closing the terminal ends a session or detaches it. Recommended: **A**, an interactive session detaches, `wb attach <session>` resumes it, and it ends only when `claude` exits. The sub-decisions below cover sleep, failure, signals, and exit codes. Accepting adds a session lifecycle section with the state diagram to S06-vm-lifecycle and `wb attach` to S05-cli, and unblocks the terminal stream contract of I52.

## The spec change

What option B became, with the sub-decisions it left open written the strict way:

- **States** (S06-vm-lifecycle, "Session lifecycle"): starting, running, paused, ending, ended and lost, with no detached state. A session has one client, the `wb` that started it.
- **Hangup:** when `wb` gets `SIGHUP` or its connection to `wb-hostd` closes, `wb-guestd` closes the session's terminal device, so `claude` gets `SIGHUP` from the guest kernel, and kills its process group 10 seconds later if it is still running. WIP is then committed and pushed as on a normal exit (S08-workspace-and-git, "Session end").
- **`--continue`:** Claude Code keeps conversations per working directory, and each session has its own worktree path. So `wb-guestd` links each new worktree's history directory to one directory per project, as the project user. That rests on Claude Code's storage layout, which was read on the host, not checked in a guest.
- **Socket drops:** the session's processes stop. When the link returns, `wb-guestd` resumes them only when `wb-hostd` says the session still has its `wb`, and otherwise ends the session. A session paused for 30 seconds of host time awake is lost.
- **Lost:** a VM, `wb-guestd` or `wb-hostd` that stops loses its sessions, and `wb` exits 255. At the next connection to that VM, `wb-hostd` has `wb-guestd` commit and push each lost session's WIP. A lost session stays live for `export.git` until then.
- **Idle suspend:** never while the VM has a session. `wb vm suspend` and `wb vm stop` are refused while it has one. A terminal left open keeps the VM up.
- **Exit status** (S05-cli, "Exit status and signals"): `claude`'s code, 128 + n for signal n, 2 for a usage error, 255 for every other Wraith Box failure, a WIP push that failed included. Interactive use means both standard input and standard output are terminals.
- **Signals:** keyboard signals are bytes in the stream. `wb` forwards `SIGINT`, `SIGQUIT` and `SIGTERM`. Ctrl-Z stops `wb` too, after it resets the terminal, and `fg` continues both.

## Options

The options are mine, built around the issue's recommendation, which is option A.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Detach, and wb attach

Losing the client detaches an interactive session. `claude` keeps running, and `wb attach <session>` shows it again. The session ends when `claude` exits, or on `wb end <session>`, a new command. Pipe and `-p` sessions and ephemeral sessions end with their client.

- **Cost:** a new state and two commands. Forgotten sessions keep a worktree and a guest process, but don't keep the VM awake (sub-decisions).
- **Differs from `claude`:** closing a terminal running plain `claude` kills it.

</div>
<div class="wb-option">

### B. Closing the terminal ends the session

`wb-guestd` sends `claude` a hangup, then commits WIP and pushes, as on a normal exit. A new `wb claude --continue` resumes the conversation.

- **Cost:** the least work. The new session starts from the host's `HEAD`. The files the old one left uncommitted are only in its WIP branch.
- **Same as `claude`** for the terminal, and a closed laptop lid over SSH loses the session.

</div>
<div class="wb-option">

### C. Detach for a grace period

As A, but a detached session ends as in B after a set time, for example 30 minutes.

- **Cost:** as A, plus a timer. A long autonomous task is killed when the user walks away, which is the case detach is for.

</div>
</div>

Each option leaves the `SEC*` controls unchanged. `wb attach` shows guest output, so it follows the same rule as a session: no approval prompts in that terminal (SEC14-no-fake-approvals).

<Aside type="note" title="Missing from the issue">
**"Running foreground process" never goes idle.** The issue blocks idle suspend while a session has "a running foreground process". In a detached session `claude` is always running, so under option A the forgotten session would keep the VM up forever, against NFR03-footprint. This brief recommends defining idle by activity instead (sub-decisions).

**A wb-guestd restart ends sessions.** `wb-guestd` holds the terminal device of each session. When it exits, `claude` loses its terminal and gets a hangup, so the issue's "`wb-guestd` restarts mid-session" is the same case as a VM crash: the session is lost.

**Detach needs a WIP snapshot.** S08-workspace-and-git pushes WIP only at session end. Under option A, one detached session may run for days, and the VM can crash meanwhile. A snapshot pushed on detach and before each suspend, written without touching the agent's worktree or index, keeps the host copy current.
</Aside>

## Sub-decisions

| Item | Recommendation |
|---|---|
| When idle suspend may happen | When no client is attached and the VM has had no session output, guest CPU load, or open guest connections for the idle period. A detached session alone doesn't block it. `wb attach` restores the VM. |
| Host sleep | The VM pauses with the host. On wake `wb-guestd` resynchronizes the clock (S06-vm-lifecycle). The session continues whether attached or detached. |
| Socket drops | As S13-guest-confinement says: the session's processes stop, and resume when the link returns. A restore after idle suspend is that case. |
| VM dies, or `wb-guestd` exits | The session is lost. `wb` prints a `wraith box:` line and exits 255. The worktree stays on the data disk, and at the next VM start `wb-hostd` has `wb-guestd` commit and push its WIP. |
| Exit codes | `claude`'s own code. 128+n when `claude` was killed by signal n. 255 when the session was lost or `wb` failed after the start. 2 for usage errors before the start (S05-cli). `claude` can also exit 2 or 255. The stderr line tells them apart. |
| Signals | Interactive: Ctrl-C, Ctrl-Z and the rest are bytes in the terminal stream, window size changes are forwarded, and `SIGHUP` or `SIGTERM` to `wb` detaches. Non-interactive: `SIGINT`, `SIGTERM`, and `SIGHUP` are forwarded to `claude`, and `wb` waits for its exit code. |
| WIP push | At session end, as S08-workspace-and-git says. Also a snapshot to `wb/<session-id>/wip` on detach and before suspend, which the landing repository's ref rule already allows. |
| Two clients | One attached client per session. A second `wb attach` takes over and the first one detaches. |
| Parallel sessions | Unchanged: a worktree and session id each (S06-vm-lifecycle, S05-cli). Each `wb` prints its own summary. A session that ended detached shows its summary in `wb sessions`. |

## Evidence

- <Badge text="verified" variant="success" /> S05-cli specifies the summary on exit and the exit code of `claude`, and doesn't list an `attach` or `end` command. The command table in `packages/wraithbox-go/internal/cli/cli.go` has neither, so both names would be new and reserved.
- <Badge text="verified" variant="success" /> When the host-guest socket drops, `wb-guestd` stops the session's process group and resumes it when the link returns (S13-guest-confinement, "Layer 1").
- <Badge text="verified" variant="success" /> Idle VMs are saved and stopped, and the next session restores them (S06-vm-lifecycle, "Warm start").
- <Badge text="verified" variant="success" /> WIP is committed and pushed at session end, `wb` may push mid-session, and the landing repository accepts only `refs/heads/wb/<session-id>/*` (S08-workspace-and-git, "Out of the guest").
- <Badge text="verified" variant="success" /> A new session's worktree starts at the host's current `HEAD` (S08-workspace-and-git, "Into the guest"), which is why B loses the open files of the old session.
- <Badge text="verified" variant="success" /> `ssh` "exits with the exit status of the remote command or with 255 if an error occurred" (`man ssh`, OpenSSH 10.3). A command killed by signal n returns 128+n (`man bash`).
- <Badge text="verified" variant="success" /> `git stash create` makes a commit "without storing it anywhere in the ref namespace" (`git help stash`), but includes tracked files only.
- <Badge text="inferred" variant="note" /> So the snapshot needs a temporary index to include untracked files. Doing it without touching the agent's index is an implementation detail for the M4 work.
- <Badge text="inferred" variant="note" /> A `wb-guestd` exit closes the terminal device it holds, and `claude` gets a hangup. The PTY rule is standard Unix behavior. That `wb-guestd` holds the PTY follows from S06-vm-lifecycle ("run commands as a project user with a PTY").
- <Badge text="assumed" variant="caution" /> That host-guest socket connections drop on save and restore, so "paused" covers idle suspend. X18-vsock-handoff checks descriptors across save and restore.
- <Badge text="assumed" variant="caution" /> That `claude` continues cleanly after its processes were stopped for hours, retrying model API calls that timed out. Cheap to check once X02-warm-start has a VM that suspends.

<summary>Details and glossary</summary>

**Why A for non-interactive sessions is different.** A piped session (`wb claude -p "…" | jq`) has no one to come back to it: its input and output are tied to the pipe. Ending it with the client is what a script expects.

**Why ephemeral sessions end with the client.** FR14-ephemeral promises no persisted state. A detached ephemeral session would keep its throwaway user and files until someone ends it.

**Why a second attach takes over.** Sharing one session between terminals would need rules for whose window size wins and who may type. Taking over is what most users expect after moving to another terminal.

**Glossary**

- **Session:** one run of `claude` in its own git worktree, with an id like `myrepo-20261003-1412-k3f9`.
- **Attach and detach:** connecting a terminal to a running session, and leaving it running without one, as `tmux` does.
- **PTY:** the terminal device a program like `claude` draws on. Its other end is held by `wb-guestd`.
- **Hangup:** the signal a program gets when its terminal goes away. Most programs exit on it.
- **WIP commit:** a commit of everything uncommitted in the worktree, marked as work in progress, so nothing is lost.
- **Idle suspend:** saving the VM's state to disk and stopping it after a quiet period (NFR03-footprint).

</details>
