## Options

The spike leaves three choices open: what happens to `/copy`, to Claude Code's desktop notifications, and to hyperlinks. The cards below cover the first two. Hyperlinks have their own cards after them, and combine with any of A, B or C.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Allowlist as measured

Take the list in X19-terminal-filter into I37. OSC 52 is dropped, and notifications become a bell. Which links stay links depends on the hyperlink choice below.

- **Cost:** `/copy` says "Copied" but the host clipboard is unchanged until I38 gives the clipboard a design. No text in "Claude needs your permission".
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="success" /> <Badge text="SEC14-no-fake-approvals" variant="caution" /> in part until I37 (title and bell) <Badge text="FR12-clipboard" variant="success" />

</div>
<div class="wb-option">

### B. Allowlist, OSC 52 becomes a clipboard request

As A, but `wb` turns each OSC 52 write into a request to copy that text to the host clipboard, approved by the user (FR12-clipboard).

- **Cost:** an approval flow for the clipboard now, which B38-port-forward-clipboard deferred past V1.
- **Keeps:** <Badge text="FR12-clipboard" variant="success" /> if approval is outside the agent's terminal. <Badge text="SEC14-no-fake-approvals" variant="caution" /> in part, as in A.

</div>
<div class="wb-option">

### C. Pass notification text

As A, but OSC 9 and OSC 777 pass. The desktop shows Claude Code's own notification text.

- **Cost:** none for the user, but a spec change: SEC14-no-fake-approvals would need an exception, and AGENTS.md does not allow weakening a control.
- **Weakens:** the guest writes text into host desktop notifications, where approvals also arrive. <Badge text="SEC14-no-fake-approvals, spec change" variant="danger" />

</div>
</div>

**Hyperlinks.**

Claude Code links file paths, web addresses and its own help pages with OSC 8. A link's visible text can differ from where it goes, and a link to `localhost` or a private address names a service on the host, not in the guest.

<div class="wb-options">
<div class="wb-option" data-recommended>

### H1. Drop OSC 8 in V1

No hyperlinks from the guest. The terminal still makes a bare web address clickable by itself.

- **Cost:** every link Claude Code draws becomes plain text, including "Security guide" style links whose address is not on screen.
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="success" />, and the filter does not need to follow the screen.
- **Decided with an addition (I30):** `wb` logs each dropped URL with its link text and lists them in the session summary, so a link whose address isn't on screen is still reachable.

</div>
<div class="wb-option">

### H2. Keep `https://` with host rules

Pass OSC 8 only for `https://` to public dotted hostnames: no IP literals, no `localhost`, `.local` or `.internal`, no user name in the URL.

- **Cost:** a link's text can still differ from its target, which T00-index would record as a residual risk.
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="caution" /> with the residual risk written down.

</div>
<div class="wb-option">

### H3. Pass a link only when its text is its URL

The filter keeps a link only if the characters between its start and end equal its URL.

- **Cost:** the filter has to track what lands on screen between the two sequences, a larger parser of guest bytes. Most of Claude Code's links fail the test and become plain text anyway.
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="success" />

</div>
</div>

<Aside type="note" title="Not an option">
Passing OSC 52 to the terminal unchanged would give the guest the host clipboard without approval, which FR12-clipboard rules out and B37-terminal-boundary already decided against.
</Aside>

<details>
<summary>Details and glossary</summary>

**How the filter works.** It splits the stream into text, controls, and escape sequences. It passes a sequence only when a rule allows it and drops any other whole, from its `ESC` to its end. The terminal never sees the start of a dropped sequence. Each drop is counted by rule, so the session summary can say why something looked wrong (NFR06-explained-refusals).

**Why file links go.** Claude Code links the paths it shows with `file://` URLs. In a guest those are guest paths. On the host they name another file or none, and a click opens whatever is there.

**Glossary**

- **Escape sequence:** bytes starting with `ESC` that a terminal treats as a command, not text.
- **OSC 52:** the sequence that sets the terminal's clipboard.
- **OSC 8:** a hyperlink around some text.
- **OSC 9, OSC 777:** desktop notifications in iTerm2 and Ghostty.
- **Kitty graphics:** a protocol for images in the terminal, one mode of which reads a file by its path.
- **Headless emulator:** a terminal emulator in a library, with no window, used to compare screens.

</details>
