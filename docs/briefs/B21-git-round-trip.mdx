<Aside type="tip" title="What we learned">
**Yes, with conditions.** The guest cloned, fetched and pushed through a remote helper over a socket, with no write to your repository and no push outside its own `wb/<session>/` branches, in every abuse case tried. The spec as written is wrong in two places. Fetching straight from your repository leaks hidden objects to anyone who knows their ID, which the export repository from B41-git-data-scope fixes. And the first push into an empty landing repository sends the whole history, which borrowing objects fixes. The recommended guard on pushes is a small Go filter, with git's own setting behind it. Accepting it merges the S08-workspace-and-git changes, which fetch from the export repository as I41 decided, and settles item 5 of I41.
</Aside>

## Options for the push guard

S08-workspace-and-git said refs are "restricted to `refs/heads/wb/<session-id>/*`" without saying what restricts them. I41 left this to the spike.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Go filter, git's hidden refs behind it

`wb-hostd` reads the list of refs a push wants to update before git sees it, and refuses the whole push if any ref is outside the session's branches. Git's `receive.hideRefs` setting checks the same thing again.

- **Cost:** about 250 lines of Go in the spike, with a fuzz target. It is a new parser of guest bytes.
- **Gives:** refusal before git parses the pack, one log line per ref with the rule, all-or-nothing pushes.
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="success" /> <Badge text="SEC10-audit" variant="success" />

</div>
<div class="wb-option">

### B. Git's hidden refs alone

What B41-git-data-scope recommended for item 5: `receive.hideRefs` hides everything but the session's branches, and git refuses a push to a hidden ref.

- **Cost:** none, a git setting.
- **Gaps:** accepted a push to `refs/heads/wb/<session>` itself (one run, Homebrew git), which blocks every later session branch. Applied the allowed half of a mixed push. Logs nothing in `wb-hostd` unless it parses git's answer.
- **Keeps:** <Badge text="FR03-work-as-branch" variant="caution" />

</div>
<div class="wb-option">

### C. Receive side in Go

Replace `receive-pack` with a Go implementation (for example go-git), so host git never parses guest packs.

- **Cost:** large. Object checking as complete as git's fsck is the hard part, and none of it was tried.
- **Keeps:** <Badge text="SEC03-no-host-exec" variant="success" /> if the checks are complete.

</div>
</div>

<Aside type="note" title="Missing from the spec">
- **Fetching from your repository leaks by ID.** With every ref but the session's branch hidden, protocol v2 still served a hidden branch's commit, a commit only on a release branch, and an unreferenced blob, with both Homebrew git and Apple git. The export repository refused all three. It must store a copy of every object it serves, not borrow from your repository.
- **The first push sends everything.** An empty landing repository made the guest send 425 MiB of Go history for a 3-commit push. Borrowing objects from the export repository cut that to 12 objects.
- **Default object checks miss some.** A tree with a bad file mode passed `receive.fsckObjects` until that check was raised to an error.
- **The helper picks the protocol.** Git doesn't tell a `connect` helper which version it wants. The helper asks for v2 itself.
</Aside>

## Evidence

- <Badge text="verified" variant="success" /> Clone, incremental fetch and push through `git-remote-wb` over a socketpair, Go repository (679,335 objects, 426 MiB), git 2.56.0 and Apple git 2.54.0. First clone 16.3 s median through the tunnel, against 17.1 s for a local clone without it. A fetch of 200 new commits 0.6 s, a 3-commit push 0.1 s. Source: X07-git-round-trip, "Measurements", and `results/run1.txt` to `run6.txt` on the spike branch.
- <Badge text="verified" variant="success" /> Protocol v2 `upload-pack` with `uploadpack.hideRefs` and every `allow*SHA1InWant` off served three unadvertised objects by ID. The export repository refused them on the server side under v2. The guest's own git client refused to send the v0 request, so the server side under v0 against a hostile client wasn't tested. Source: `results/run2.txt` and `run3-apple.txt`, "Hidden data".
- <Badge text="verified" variant="success" /> The Go filter refused pushes to `main`, a tag, another session, a lookalike session `S10`, the bare session ref, deletes, and a mixed push, with landing unchanged in every case. Source: `results/run5.txt` and `run3-apple.txt`, "Push abuse".
- <Badge text="verified" variant="success" /> `receive.hideRefs` alone created `refs/heads/wb/S1` from a push to that name (one run, Homebrew git, `results/run5.txt`), and applied the allowed ref of a mixed push (`run3-apple.txt`, `run5.txt`).
- <Badge text="verified" variant="success" /> Strict fsck refused trees with `.git`, `.GIT`, `git~1`, `..`, symlinked `.gitmodules` and `.gitattributes`, mode `100666`, a bad commit date, and a `.gitmodules` URL starting with `-`. Garbage, truncated and bit-flipped packs were refused. Your repository's files were unchanged across the raw protocol attacks. Source: `results/run3-apple.txt`, "Push abuse" and "Raw protocol abuse".
- <Badge text="verified" variant="success" /> Push commands sent to `upload-pack` ended in a protocol error, and `wb-hostd` refused other services, extra arguments and bad protocol values before running git. Source: `results/run3-apple.txt`, "Raw protocol abuse".
- <Badge text="verified" variant="success" /> The flagger flagged 2% of 400 Go commits, 17% of 400 Express commits and 51% of 43 Wraith Box commits, at 11 to 18 ms per commit. Source: `results/run2.txt`, "Risky-path flagger".
- <Badge text="inferred" variant="note" /> v2 `upload-pack` also serves objects from a borrowed object store, since it served an unreferenced object (`results/run2.txt`), though no run tried a borrowed store. So the export repository stores a copy of every object it serves.
- <Badge text="assumed" variant="caution" /> That vsock behaves like the socketpair: a byte stream with half-close. X18-vsock-handoff tests vsock in a macOS guest.

<details>
<summary>Details and glossary</summary>

**Why a filter and not only git.** Git checks hidden refs after it has read and unpacked the pack, one ref at a time. The filter reads only the short list of refs at the start of the push, so a refused push never reaches git's pack parser, and the refusal names the session's prefix. Keeping `receive.hideRefs` as well means a bug in either layer alone does not open the landing repository.

**Why the landing repository borrows.** Git sends what the receiving side doesn't have. An empty landing repository has nothing. The guest then sends the project's whole history on its first push. With the export repository listed as an alternate object store, the landing repository already has that history. Garbage collection on the export repository must then keep what landing branches still use (I41, item 6).

**Glossary**

- **Remote helper:** a program git runs to reach a remote it has no built-in transport for. `git-remote-wb` handles `wb::` URLs.
- **`connect` capability:** the helper only opens a byte stream to the remote git program and copies bytes both ways.
- **Pkt-line:** git's framing: a 4-digit hex length, then the data.
- **Command list:** the lines at the start of a push that say which ref moves from which commit to which.
- **fsck:** git's object checker.
- **Alternates:** a list of other object stores a repository may read objects from.
- **Socketpair:** two connected sockets in one machine, used here in place of vsock.

</details>
