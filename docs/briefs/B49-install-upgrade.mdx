<Aside type="tip" title="You are deciding">
Which process downloads macOS restore images. Recommended: **A**, `wb-proxyd`, under a built-in rule for Apple's hosts only, writing into a file `wb-hostd` opens for it. The issue proposes **B**, `wb-hostd`. The sub-decisions on install, upgrade and migration can be decided now as well. Signing, Keychain access after an upgrade, and the guest tools image wait on X09-keychain-unsigned and X17-image-build.
</Aside>

## Options

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. wb-proxyd downloads

`wb-hostd` opens the target file and asks `wb-proxyd` to fill it. A built-in rule allows only Apple's catalog and download hosts, and the download is audited like any other connection. `wb-hostd` checks the hash before `wb-vmd` may use the file.

- **Cost:** one RPC and one fixed rule. `wb-proxyd` does more than serve guests, as it already does for vulnerability lookups (SEC07-dep-gate).
- **Keeps:** <Badge text="SEC12-least-privilege" variant="success" /> <Badge text="SEC10-audit" variant="success" />

</div>
<div class="wb-option">

### B. wb-hostd downloads

The issue's proposal. `wb-hostd` fetches from Apple's catalog only and checks the catalog's hash.

- **Cost:** the least code. `wb-hostd`'s self-sandbox gains outbound network (S04-architecture lists only its state directories), and the download needs its own audit and its own upstream proxy settings.
- **Keeps:** <Badge text="SEC12-least-privilege with a wider sandbox" variant="caution" />

</div>
<div class="wb-option">

### C. wb downloads

`wb image build` downloads in the foreground and hands the file to `wb-hostd`. No daemon gains network.

- **Cost:** the download stops when the terminal closes and resumes on the next run. Inside WSL `wb` runs on the wrong side for later Linux images (S12-platforms, "WSL").
- **Keeps:** <Badge text="SEC12-least-privilege" variant="success" />

</div>
</div>

A fourth choice, `wb-vmd` downloading through the Virtualization framework's own catalog call, is ruled out today: S04-architecture gives `wb-vmd` no network. X17-image-build may reopen it if the install needs network anyway.

<Aside type="note" title="Missing from the issue">
**B breaks two stated rules.** S04-architecture gives `wb-hostd` "its state directories" and `wb-proxyd` "outbound network". The code comment on `wb-proxyd` says it "is the only Wraith Box process that connects upstream" (`packages/wraithbox-go/cmd/wb-proxyd/main.go`). B changes both, and A keeps both, so this brief recommends A over the issue's proposal.

**The install itself may need network.** Installing macOS into a new VM may contact Apple to personalize the install. That call would come from `wb-vmd`, which S04-architecture says has no network. X17-image-build should check this, because the answer may force a spec change for `wb-vmd` whichever option is chosen.

**Finding the newest image is a Swift API.** The Virtualization framework's call for the newest supported restore image runs in the calling process. Under A or B, Go must read Apple's catalog directly. That needs a catalog with a stable address and a hash per image. Also X17-image-build.
</Aside>

## Sub-decisions

| Item | Recommendation | Waits on |
|---|---|---|
| Image source | Apple's catalog only, or a local restore image file the user names (for offline and managed machines). | X17-image-build, for the hash |
| What `wb setup` installs | A LaunchAgent plist for `wb-hostd` in `~/Library/LaunchAgents`, loaded for the user only, and a `wb` link in a per-user directory, with the `PATH` line printed. Nothing that needs administrator rights (SEC12-least-privilege). | X09-keychain-unsigned, for whether a signed bundle can register itself instead |
| Uninstall | `wb setup --remove` stops the services and removes the plist and the link. It keeps `<config>`, `<data>`, `<logs>` and Keychain items unless `--purge` is given. | nothing |
| Upgrades | Replace the whole bundle, then I48's sequence: save VMs, restart, restore. No in-place update of a running bundle. | I48 |
| Migrations | `wb-hostd` at start, never `wb`. Back up `state.db` first, apply numbered migrations forward only, and refuse to start on a database newer than it knows, with a message saying why (NFR06-explained-refusals). User-edited configuration files are never rewritten: a renamed key is an error naming the new key. | nothing |
| Guest tools disk image | Built with the bundle from `wb-guestd` and `git-remote-wb`, with the bundle's version, attached read-only (S06-vm-lifecycle). | X17-image-build, for signing inside the guest |
| Keychain after an upgrade | Whatever X09-keychain-unsigned shows. If an ad-hoc signed `wb-proxyd` loses its access-list entry at each upgrade, `wb setup` must say so and offer to grant it again. | X09-keychain-unsigned |
| Build order in `mise` | `go build`, then `swift build`, then the guest tools image, then the bundle, then ad-hoc signing from the inside out (`codesign -s -`), with the virtualization entitlement on `wb-vmd` only (S10-tech-stack). | nothing |

<details>
<summary>Details and glossary</summary>

**The download isn't a security boundary.** T00-index trusts the operators of allowlisted services, Apple included. The danger isn't Apple's content but giving a long-lived daemon a network path it doesn't otherwise need. A keeps the one process that already has that path as the only one.

**Migrations belong to wb-hostd.** Each terminal runs its own `wb` process, and during an upgrade they may briefly be different versions. `wb-hostd` alone owns `state.db`, so only `wb-hostd` can safely change its layout.

**Glossary**

- **Restore image:** Apple's macOS installer file (`.ipsw`, around 15 GB) that the Virtualization framework installs into a new VM.
- **Catalog:** Apple's list of current restore images and their download addresses.
- **Personalization:** Apple's servers signing an install for one device, which recent macOS installs require.
- **Guest tools disk image:** a read-only disk with `wb-guestd` and `git-remote-wb` that `wb-hostd` attaches to a VM to install or update them.
- **Ad-hoc signing:** signing a binary without a developer identity. macOS on Apple Silicon requires at least this, but it identifies only that exact file.
- **Migration:** a step that changes the layout of stored data from one version to the next.

</details>
