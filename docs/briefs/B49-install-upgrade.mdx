## What approving commits to

- **A new process, `wb-download`.** One run per download, started through `wb-launcher` from two fixed entries: `wb-download-restore` (Apple's `mesu.apple.com` and `updates.cdn-apple.com`) and `wb-download-claude` (`downloads.claude.ai`). It writes only to files `wb-hostd` opened and doesn't follow redirects or read a proxy setting. Its profile denies files, the secret store and starting programs.
- **The restore image** is the newest in Apple's catalog that isn't newer than the host's macOS. `wb-hostd` checks its size and SHA-1, resumes a partial download, refuses one without room, and deletes the image once a build has sealed its image.
- **Claude Code** comes from a path fixed per guest platform (`<version>/darwin-arm64/claude`), so `wb-download` parses nothing, and `wb-release-check` now also checks the manifest's `binary` field.
- **The build order** of `mise run build` on macOS: version stamp, Go, Swift, `xcodebuild` of a committed app project (`packages/wraithbox-swift/WraithBox.xcodeproj`), the guest tools disk, assembly, signing from the inside out, checks. CI builds the ad-hoc bundle on every pull request.
- **`wb setup`** writes `~/Library/LaunchAgents/nl.wraithbox.hostd.plist` and links `~/.local/bin/wb`. `wb setup --remove` deletes both and keeps data and store items.
- **Upgrades** replace the bundle by rename, never by copying over it. Then S04-architecture's restart applies.
- **Migrations** run in `wb-hostd` only, forward only, after a backup. A failed migration or a newer database puts `wb-hostd` in a refusing mode instead of a restart loop.

## Options for trusting the restore image

Apple's catalog lists only a SHA-1 per image, and isn't signed. The hash check catches a damaged or swapped file. A compromised `wb-download` that reports its own URL and hash gets past it.

<div class="wb-options">
<div class="wb-option" data-recommended>

### A. Catalog SHA-1, plus Apple's check at install

`wb-hostd` checks the file against the catalog's SHA-1. Against a compromised downloader, the design relies on Virtualization's installer refusing an image Apple didn't sign, which I262 measures.

- **Cost:** none beyond the spec. A new macOS release works the day Apple lists it.
- **Keeps:** <Badge text="SEC12-least-privilege" variant="success" /> <Badge text="SEC08-proj-isolation" variant="caution" /> if I262 holds

</div>
<div class="wb-option">

### B. Hashes pinned in each Wraith Box release

Each release compiles in the SHA-256 of the restore images it accepts, and refuses any other.

- **Cost:** a new macOS point release can't be used until Wraith Box ships a new build. Apple's catalog lists only the newest image, so an older pinned one may disappear.
- **Keeps:** <Badge text="SEC12-least-privilege" variant="success" /> <Badge text="SEC08-proj-isolation" variant="success" />

</div>
<div class="wb-option">

### C. Also the CDN's SHA-256 header

The download host sends `x-amz-meta-digest-sha256` with the file. `wb-download` would report it, and `wb-hostd` would check it too.

- **Cost:** little, but it comes from the same response and the same process as the file, so it doesn't help against a compromised downloader.
- **Keeps:** <Badge text="SEC12-least-privilege" variant="success" />

</div>
</div>

## Other open points

Each has a recommendation, which the spec states. Approving the spec accepts them.

| Point | Recommended, in the spec | Alternative |
|---|---|---|
| The restore image after a build | Deleted once the build seals its image, freeing about 27 GB. A failed build keeps it for the retry. | Kept for the next build, which then skips the download. |
| A restore image from a local file | Out of scope for V1 (I263). | `wb image build --restore-image <file>` for offline and managed hosts. |
| Uninstall | `wb setup --remove` keeps data and store items, and prints where they are (I264 for `--purge`). | A `--purge` that deletes them through their owners. |
| Where `wb` is linked | `~/.local/bin/wb`, with the `PATH` line printed. `wb setup` leaves shell files alone. | `/usr/local/bin`, which needs administrator rights on many Macs. |
| The LaunchAgent | A plist `wb setup` writes and loads with `launchctl`. | `SMAppService`, which needs a Swift or Objective-C call and an approval in System Settings. |
| The app's main executable | The notification helper. | A stub, until the helper exists. |
| The ad-hoc bundle identifier | `nl.wraithbox.dev.adhoc`, or `WB_BUNDLE_ID`. | none proposed |
| A failed migration | `wb-hostd` keeps running and refuses everything but `wb status`. | Exit, which launchd restarts in a loop. |

## Evidence

- <Badge text="verified" variant="success" /> Apple's catalog (`https://mesu.apple.com/assets/macos/com_apple_macOSIPSW/com_apple_macOSIPSW.xml`, 99,450 bytes on 2026-10-15) is an XML property list. Each restore entry has `FirmwareURL`, `FirmwareSHA1`, `ProductVersion` and `BuildVersion`, and no other hash. It lists one image, 27.0.1 (26A434), at `updates.cdn-apple.com`. Probe: `curl` and `plutil -convert json`.
- <Badge text="verified" variant="success" /> The download host answers with `Content-Length: 26637307067`, `Accept-Ranges: bytes` and a `206` for a range request, so a download can resume. It also sends `x-amz-meta-digest-sha256`. Probe: `curl -I` and `curl -r 0-15`.
- <Badge text="verified" variant="success" /> Apple's hosts served the catalog and the image without a redirect, and `downloads.claude.ai` served `manifest.json` (1,897 bytes), `manifest.json.sig` (833 bytes) and `darwin-arm64/claude` (249,556,880 bytes) for 2.1.300 without a redirect. The manifest's `binary` field is `claude`. So "no redirects" and the size caps fit. Probe: `curl -I`.
- <Badge text="verified" variant="success" /> A confined Go program reaches TLS hosts only when its profile allows the certificate check services. Source: X23-sandboxed-daemons, "wb-proxyd: the network part".
- <Badge text="verified" variant="success" /> A team-signed helper must be its own bundle, and the build gets the profile from an Xcode project. Source: X29-dev-signing.
- <Badge text="verified" variant="success" /> X17-image-build installed macOS from a local restore image in 271.6 s, with no download in `wb-vmd`.
- <Badge text="inferred" variant="note" /> Seatbelt's network rules can name a port but not a remote host, so the host allowlist is in `wb-download`'s code. Source: the profiles of X23-sandboxed-daemons, which allow outbound TCP by port.
- <Badge text="inferred" variant="note" /> macOS shows a notification under the bundle of the process that posts it, so the notification helper is the app's main executable.
- <Badge text="assumed" variant="caution" /> Virtualization's installer refuses a restore image that Apple didn't sign. Option A relies on it against a compromised `wb-download`. I262 measures it, and needs a VM.
- <Badge text="assumed" variant="caution" /> A raw disk image with one APFS volume, made with `hdiutil`, works as the guest tools disk. Virtualization attaches raw images, and the first `app:bundle` build checks the rest.

<details>
<summary>Details and glossary</summary>

**Why a program of its own.** The 2026-10-04 decision on I49 chose a dedicated program over `wb-proxyd` (this brief's earlier recommendation) and `wb-hostd` (the issue's proposal). `wb-hostd` faces the guest, so it stays off the network. `wb-proxyd` faces the guest's traffic and holds credentials, so it doesn't take on more. `wb-download` holds no credential, doesn't face a guest, and runs only during an image build.

**Why `wb-hostd` opens the files.** `wb-download`'s profile denies every file path, so it can only write where `wb-hostd` pointed it. It can't touch an image, a VM bundle or a credential.

**Why a refusing mode.** launchd restarts `wb-hostd` whenever it exits (S04-architecture). A `wb-hostd` that exited on a database it can't read would start again at once, forever. Staying up lets `wb status` say why.

**Glossary**

- **Restore image:** Apple's macOS installer file (`.ipsw`, about 27 GB) that Virtualization installs into a new VM.
- **Catalog:** Apple's list of current restore images, with each one's address and SHA-1.
- **LaunchAgent:** a file in `~/Library/LaunchAgents` that tells macOS to run a program for one user and restart it when it exits.
- **Ad-hoc signing:** signing without a developer identity (`codesign -s -`). Such a build has no Keychain backend.
- **Migration:** a step that changes the layout of stored data from one version to the next.
- **SHA-1:** an older hash. Anyone can now make two files with the same SHA-1, but no known attack makes a file that matches an existing file's SHA-1.

</details>
